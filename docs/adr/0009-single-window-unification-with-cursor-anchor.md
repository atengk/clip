# 退役迷你卡片并统一为随光标吸附的全功能主面板架构决策

## 背景与问题 (Context)

在引入免激活迷你紧凑卡片（`Compact Popover`, 340×460）后，虽然在 Windows 资源管理器重命名等就地编辑场景下尝试了保持原编辑态的方案，但在实际用户使用体验中暴露出以下关键痛点：
1. **交互割裂与高操作成本**：Alt+V 唤出后默认展示紧凑卡片，用户若需要进行实时拼音搜索、分类切换或常用语选择，必须额外按 Tab 键展开至完整面板，增加了认知与按键负担；
2. **免失焦与输入焦点冲突**：为了不抢夺前台编辑框焦点而引入的 `WS_EX_NOACTIVATE` 导致面板无法接收常规 Windows 键盘输入，必须依赖 Win32 底层输入钩子（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`）转发，系统复杂度高且容易引发按键截断或通信风险；
3. **用户核心述求收敛**：用户明确决策“只搞一种界面，迷你那个给我删了”，要求简化界面形态，同时保留快捷键唤出时“随着鼠标光标走”的核心体验。

## 方案选型与决策 (Decision)

我们决定彻底退役迷你紧凑卡片（`Compact Popover`）及其相关的 Win32 免激活扩展样式与底层钩子守护线程，统一为唯一的 660×520 全功能主面板：

1. **界面体系单一化**：彻底移除 `CompactPopover.tsx` 及其 CSS 样式，只保留经过打磨的 660×520 全功能主面板，内建完整的拼音/首字母模糊检索输入框、分类胶囊标签、常用短语库、调色板及设置中心。
2. **智能光标吸附定位 (WindowAnchor + Flip-fit)**：快捷键（如 Alt+V）呼出时，依然通过 Win32 API 优先获取活动前台输入光标（Caret），若获取失败则平滑降级至鼠标指针（Cursor Pos），并经由 `Flip-fit Anchor` 算法完成四向翻转避让与工作区钳位，将 660×520 主面板精准呈现在光标旁边；系统托盘或菜单触发时则默认居中弹出。
3. **恢复常规输入焦点**：呼出后主面板正常获取系统焦点，搜索输入框自动聚焦并选中文本，支持即打即搜、↑/↓ 键切换、1~9 快速数字键回填、Space 预览与 Enter 粘贴，彻底消除多层级按键转发机制。
4. **就地重命名探测与重激活补偿 (In-place Renaming Compensator)**：
   - **呼出前态感知**：快捷键呼出前采集前台窗口上下文，当顶层窗口为 Windows 资源管理器或桌面（`CabinetWClass` / `ExploreWClass` / `Progman` / `WorkerW`）且键盘聚焦子控件类名为 `Edit` 时，精确标记 `IS_EXPLORER_RENAMING`；
   - **回填时重激活**：主面板正常获得键盘焦点供用户打字搜索；当用户确认回填时，Clip 隐藏自身并恢复资源管理器前台焦点（等待 35ms），随后模拟发送 `VK_F2` 使目标文件重新进入重命名全选编辑态（等待 25ms），最后发送 `Ctrl + V` 完成精准回填。
5. **架构极致精简**：彻底清理 Windows 专属底层钩子线程与 `WS_EX_NOACTIVATE` 免激活样式操作，代码复杂度大幅下降，测试确定性显著提升。

## 架构影响 (Consequences)

- **优势**：
  - 用户体验高度统一流畅，呼出即可直接拼音打字检索，彻底消除割裂的多卡片模式切换；
  - 完美满足“随着光标/鼠标走”的空间就近性需求；
  - 移除了 Windows 全局底层输入钩子守护线程，避免潜在系统安全软件拦截风险与进程资源开销；
  - 通过 `In-place Renaming Compensator` 精准攻克 Windows 资源管理器重命名失焦痛点，兼顾“打字搜索焦点”与“重命名就地回填”两大诉求；
  - 单测与 E2E 回归套件保持 100% 毫秒级确定性通过。
- **权衡**：在就地重命名补偿回填时需执行微秒级（35ms + 25ms）时序等待以保证资源管理器 Edit 控件完成就绪重建，在日常普通文本编辑场景则保持零延迟瞬时直贴。
