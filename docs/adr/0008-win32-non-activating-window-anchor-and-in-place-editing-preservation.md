# Win32 免失焦光标吸附与就地编辑保持架构

在 Windows 资源管理器重命名或轻量文本编辑时，传统弹窗通过 `SetForegroundWindow` 激活会强制导致宿主编辑框失焦（`WM_KILLFOCUS`）并提前终止编辑，导致剪贴板回填失败。为了达成类似原生 `Win + V` 的无缝就地粘贴体验并实现智能光标吸附，我们决定将呼出面板重构为免激活悬浮窗（`Non-Activating Popup`），优先锚定文本输入光标（Caret Anchor）并回退至鼠标指针（Pointer Anchor），结合四向翻转（`Flip-fit Anchor`）与低级按键拦截分发，保障在任何就地编辑状态下均可安全回填。

## 方案选型与权衡 (Considered Options)

1. **普通置顶大窗口并抢占系统焦点 (现状)**：开发简单，但资源管理器重命名在失焦瞬间直接被销毁，根本无法粘贴回填。
2. **免激活悬浮（WS_EX_NOACTIVATE）+ 低级输入挂钩分发 (采纳)**：面板显示不抢夺宿主焦点，保持重命名编辑框存活；通过 `WH_KEYBOARD_LL` 拦截方向键与回车完成选择并触发极速回填，彻底攻克就地编辑中断问题。
3. **免 UI 后台轮换粘贴快捷键**：虽然避免了弹窗焦点问题，但无法直观检索、过滤与预览历史条目。

## 架构影响 (Consequences)

- **优势**：完美复刻 Windows `Win + V` 的光标就地呼出与无感回填体验；重命名文件、桌面图标或内联输入框时 100% 保持编辑态。
- **代价**：免激活状态下面板无法自动接收标准键盘焦点，需由 Win32 平台驱动层纳管轻量级按键与鼠标钩子分发；跨平台实现上需在 PAL 层提供 Windows 专属驱动与非 Windows 的平稳降级适配。
