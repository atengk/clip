# 列表优先导航架构与极速回填人机工效决策 (List-First Navigation & Fast-Paste Ergonomics)

## 背景与问题 (Context)

在桌面端日常剪贴板管理流中，用户反馈了以下核心体验瓶颈：
1. **`Alt + 1~9` 响应失效**：
   - WebView2 继承自 Chromium 内核的默认加速键系统，将 `Alt + 1~8` 内部保留为标签页切换指令，在派发到 DOM 前常被丢弃；
   - Windows 操作系统下 `Alt` 键触发系统菜单逻辑并受中文输入法合成事件拦截；
   - 依赖 `e.key` 字符串判定在修饰键与数字小键盘（Numpad）下易产生键码漂移。
2. **搜索框默认强占焦点阻断盲贴 (AutoFocus Trap)**：
   - 窗口呼出时默认 `autoFocus` 抢占搜索输入框，强制进入打字状态；
   - 用户无法单按数字键直接回填前序条目，必须配合复杂的修饰键，破坏了即呼即贴的直觉心智模型。

## 方案选型与决策 (Decision)

经架构推演（`/grill-with-docs`），我们决定实施**列表优先导航模式与全键盘极速回填**架构：

### 1. 列表优先导航架构 (List-First Navigation)
- **取消默认抢焦**：面板呼出时默认不聚焦搜索框，焦点自然保持在历史列表，第一项条目默认处于选中高亮状态；
- **单键极速盲贴 (Instant Single-Key Paste)**：在列表优先模式下，单按数字键 `1~9`（支持主键盘与小键盘）直接触发对应序号条目回填至前台外部窗口；
- **键盘流全功能漫游**：
  - `ArrowDown` / `ArrowUp`：直接在列表中顺畅漫游；
  - `Enter`：直接回填当前高亮项；
  - `Space`：展开/收起右侧条目详情抽屉。

### 2. 按需激活搜索模式 (On-Demand Search Activation)
- **鼠标置入**：用户点击搜索框或清空按钮时，焦点置入搜索框，正式进入检索打字状态；
- **快捷唤醒**：在列表模式下单按 `/` 键可瞬间将光标置入搜索框，进入即时检索；
- **输入法与纯数字保真**：焦点进入搜索框后，单按数字键 `1~9` 100% 保留为搜索词纯文本打字，绝对不误触发回填；
- **退出搜索**：在搜索框内按下 `Escape`，若有搜索词则清空，无搜索词则光标退出搜索框并重回列表导航状态。

### 3. 标准化穿透修饰键升级 (`Ctrl + 1~9`)
- **替代 `Alt` 方案**：全面采用 Windows 桌面黄金标准 `Ctrl + 1~9` 作为无条件强回填热键；
- **全上下文穿透**：无论用户当前是在列表导航还是在搜索框中打字，按 `Ctrl + 1~9` 均无条件穿透输入法，直接回填对应序号条目。

### 4. 全键盘物理键码适配 (Physical KeyCode Alignment)
- 底层不再单一依赖 `e.key`，统一采用物理按键码 `e.code` 判定：
  - 主键盘数字：`Digit1` ~ `Digit9`
  - 小键盘数字：`Numpad1` ~ `Numpad9`
- 消除大小写、NumLock 锁定与操作系统字符映射差异，100% 确定性触发。

## 架构影响 (Consequences)

- **正面收益**：
  - 呼出面板后“单按 1”即贴第一项，响应极快，无需按任何组合修饰键；
  - 搜索打字与数字直贴彻底解耦，体验自然流畅；
  - `Ctrl + 1~9` 与小键盘支持彻底终结 Chromium 与 Windows 系统按键吞没问题。
- **负面成本与注意事项**：
  - 用户从“呼出立刻打字”转变为“点击或按 / 打字”，需在界面搜索框提供清晰的占位符指引（如 `按 / 或点击搜索...`）。
