# Windows 原地无感覆盖升级、安装期进程自愈与应用内一键更新架构决策

## 背景与问题 (Context)

在 Windows 平台日常分发与版本迭代中，用户反馈了严重的升级体验断层：“每次发布新版本后，必须先手动从系统卸载旧版本，才能重新安装新版本”。

经过技术探查，该问题的深层技术根因包括：
1. **Windows 文件系统独占写入锁定**：Clip 作为托盘与后台常驻剪贴板工具，`Clip.exe` 进程在后台持续运行。用户下载新版安装包（`Clip-*-Windows-x64-Setup.exe`）双击运行时，NSIS 尝试向安装目录覆写 `Clip.exe`，由于旧进程持有文件句柄被系统拒绝，导致安装失败；
2. **NSIS 安装钩子缺少进程自愈保障**：`src-tauri/windows/hooks.nsh` 中的 `NSIS_HOOK_PREINSTALL` 为空，未在安装前检测并退出运行中的旧实例；
3. **应用内版本更新未形成闭环**：检查更新弹窗仅提供了跳转 GitHub Releases 网页的外部链接，用户必须手动打开浏览器、寻找对应安装包下载并运行，流程冗长。

## 方案选型与决策 (Decision)

经过两轮设计拷问与权衡评估，我们决定实施“**NSIS 原地覆盖升级 + 运行期进程自愈 + 卸载可选清理 + 应用内一键下载更新**”的综合解决方案：

### 1. NSIS 安装期进程自愈 (Process Self-Healing)
- 在 `src-tauri/windows/hooks.nsh` 的 `NSIS_HOOK_PREINSTALL` 宏中，注入两阶段进程探测与退出逻辑：
  - **优雅退出优先**：先向运行中的 `Clip.exe` 顶层窗口广播安全关闭消息，保障 SQLite WAL 事务平滑刷盘并注销任务栏托盘图标；
  - **强制兜底保障**：若缓冲等待 1.5 秒后进程仍然持有句柄，果断执行 `taskkill /F /IM Clip.exe` 强制接管；
  - 彻底释放文件句柄，保障 NSIS 100% 顺畅原地覆盖。
- 在 `NSIS_HOOK_POSTINSTALL` 阶段：
  - 针对静默安装模式（`/S`）与常规向导模式，确保安装完成后自动以当前用户权限拉起新版本 `Clip.exe`，保障使用不中断。

### 2. 卸载期用户数据安全契约 (Uninstall Data Contract)
- **覆盖升级**：默认严格保留 `%APPDATA%\com.clip.app` 目录下的所有 SQLite 数据库、图片 Blob 缓存与用户配置，绝不触碰；
- **主动卸载**：在 NSIS 卸载向导中新增自定义复选框（Checkbox）：“同时删除剪贴板历史记录与本地数据（AppData）”，**默认保持未勾选（False）**；仅当用户显式勾选确认时，才在 `NSIS_HOOK_POSTUNINSTALL` 清除数据目录，坚决防范误操作导致数据丢失。

### 3. 应用内一键下载与静默升级闭环 (In-App Direct Upgrade)
- **弹窗交互流**：升级现有的“检查更新”弹窗（`UpdateModal`）：
  - 保留 [前往 GitHub 网页] 作为网络受限时的兜底渠道；
  - 新增 [一键下载并安装] 主操作按钮；
  - 点击后弹窗进入锁定态，呈现高密度进度条（已下载/总大小、百分比与下载速度），支持用户随时点击 [取消下载] 中断并清理临时文件；
- **校验网关 (Checksum Gate)**：
  - 后端在下载安装包的同时拉取 Release 同捆的 `checksums.txt` 清单；
  - 执行前严格校验安装包的 SHA-256 哈希值，拦截网络劫持或不完整截断包；
- **静默执行与重启**：
  - 基于当前用户权限（`currentUser` 免 UAC 弹窗）执行 `Setup.exe /S`；
  - 后端触发子进程后优雅退出应用（`app_handle.exit(0)`），安装程序原地替换后自动启动新版。

## 方案权衡与替代方案对比 (Trade-offs & Alternatives)

| 评估维度 | 方案 A: NSIS 原地覆盖 + 应用内一键静默升级 (本决策采纳) | 方案 B: 接入 Tauri 官方 Updater 插件 (`@tauri-apps/plugin-updater`) | 方案 C: 仅提供解压绿色版 (Portable ZIP) |
| :--- | :--- | :--- | :--- |
| **用户体验** | 双击安装包或应用内一键升级均无缝覆盖，自动重启 | 应用内后台拉取差量包并热更 | 需手动解压覆盖，无开机注册与卸载项 |
| **架构与依赖** | 零新增大型第三方依赖，复用现有 NSIS 与 Rust 标准库 | 需配置 Minisign 密钥对、签名证书与 `latest.json` 生成 | 极简，无安装包 |
| **运维与安全** | 无私钥泄露风险，完全复用现有 GitHub Release 构件 | GitHub CI 需托管私钥 Secrets，密钥轮换成本高 | 无 |
| **实施成本** | 低-中，改动集中在 `hooks.nsh` 与轻量下载命令 | 高，需调整多平台 Release 流水线与签名机制 | 极低 |

## 架构影响 (Consequences)

- **正面收益**：
  - 彻底终结“必须先卸载再重新安装”的历史缺陷，大幅降低用户升级心智负担；
  - 双击安装包与应用内一键升级双通道并行，升级体验达到现代主流桌面软件标杆；
  - 卸载流程提供数据保护复选框，兼顾彻底清理与防误删安全性。
- **负面成本与注意事项**：
  - 国内弱网环境下直接从 GitHub 下载安装包可能偶发网络超时，前端必须做好进度超时检测与优雅降级引导（提示前往网页下载）。
