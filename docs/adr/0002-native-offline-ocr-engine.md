# 采用操作系统原生 OCR API 实现零体积包袱的离线文字识别

为了在剪贴板管理器中提供安全、快速且无额外体积膨胀的图片文字提取能力，我们决定采用操作系统原生离线 OCR API（Windows 优先接入 `Windows.Media.Ocr`，后续在 PAL 抽象下接入 macOS VisionKit 与 Linux 轻量适配），坚决不打包大型第三方 ONNX/Tesseract 深度学习模型，亦不发起任何外部云端网络请求。

## Status

accepted

## Context

剪贴板中截图与图片的文字提取属于现代高频生产力诉求。
然而，打包预置第三方离线 OCR 引擎（如 Tesseract、PaddleOCR 或深度学习 ONNX 模型）会导致应用程序安装包体积直接暴增 40MB~80MB，且冷启动与推理资源占用显著。调用云端公有云 OCR API 又存在私密截图与机密文本外泄的严重合规与隐私风险。

## Considered Options

1. **操作系统原生 OCR（Windows.Media.Ocr / VisionKit）**：利用 Windows 10/11 内置的原生光学字符识别组件。识别准确率高、推理毫秒级、0MB 安装包额外体积增量、完全本地离线，100% 保护用户隐私。（采纳）
2. **打包嵌入式开源 Tesseract-OCR / ONNX 模型**：各平台代码逻辑统一，但导致安装包体积膨胀数倍，背离轻量级系统小工具的架构原则。（放弃）
3. **调用公有云第三方 OCR API**：需要联网、消耗外部费用、存在剪贴板图片上传的网络泄漏与安全隐患。（放弃）

## Consequences

- 客户端安装包严格维持在 10MB 左右的极简规格。
- 图像 OCR 全流程完全在本地内存与系统内核中运行，彻底断绝用户凭据或私密截屏的隐私风险。
- 各平台的 OCR 逻辑需通过平台抽象层（PAL）隔离适配，在首阶段优先交付 Windows 原生能力。
