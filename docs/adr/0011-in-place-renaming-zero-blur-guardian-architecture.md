# Windows 资源管理器重命名免失焦守护之废止与极简收敛决策 (ADR-0011)

## 背景与决策废止原因 (Context)

此前为了在 Windows 资源管理器重命名文件时保持编辑框光标不灭，引入了 `WS_EX_NOACTIVATE` 免激活样式配合独立底层输入拦截线程（`WH_KEYBOARD_LL` / `WH_MOUSE_LL`）守护方案。但在实际人机工效验证中暴露出以下问题：
1. **隐藏状态机冲突**：由于面板未获取前台系统焦点，通过快捷键唤出后若用户再次按 `Alt+V` 想要收起窗口，或者点击外部空白时，难以依靠原生窗口焦点机制稳定触发隐藏；
2. **键盘流体验割裂**：免激活态下无法使用全功能搜索输入框，必须依赖定制的键盘拦截转发，系统复杂度和维护成本过高；
3. **最终用户决策**：用户明确指示“彻底去掉重命名聚焦这一块，不要这个功能了”，要求回归简单直接的纯粹架构。

## 方案选型与收敛 (Decision)

我们决定**彻底移除重命名就地聚焦与免失焦守护相关的全部特殊逻辑**：
1. **清理 Windows 专属钩子与样式**：彻底删除 `WH_KEYBOARD_LL` / `WH_MOUSE_LL` 守护线程及其消息循环，删除 `WS_EX_NOACTIVATE` 样式读写与无激活展示 API；
2. **纯粹单一主面板**：全局保持唯一的 660×520 全功能主面板，快捷键呼出时始终正常展示并获取焦点（`window.show()` + `window.set_focus()`），支持即打即搜与回车/数字直贴；
3. **标准显隐状态机**：呼出后按 `Alt+V` 或 `Esc`、或者点击外部失焦，100% 依赖系统原生焦点生命周期进行稳定隐藏与释放。

## 架构影响 (Consequences)

- **优势**：
  - 彻底消除了底层系统级全局钩子带来的潜在冲突与复杂状态同步隐患；
  - 删除了数百行非必要的平台特定代码，代码库更加精简、高内聚；
  - 快捷键唤出与关闭行为彻底统一，无任何状态分支陷阱。
- **权衡**：在 Windows 资源管理器重命名状态下按 `Alt+V` 呼出主面板将正常获取焦点，重命名编辑框将按 Windows 原生标准行为退出。
