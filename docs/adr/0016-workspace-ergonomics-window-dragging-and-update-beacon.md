# 桌面工作区人机工效、原生窗口拖拽与更新信标架构决策 (Workspace Ergonomics, Window Dragging & Update Beacon)

## 背景与问题 (Context)

在实际桌面使用场景中，用户反馈了以下 4 项影响交互体验的人机工效与视觉问题：
1. **搜索框占位文字被截断**：
   - 顶部搜索框文案过长，而第一行右侧并排堆叠 4 组功能按钮，导致文案在 660px 窗口宽度下被生硬切断；
2. **窗口无法拖拽位移**：
   - 顶部 Header 内部元素均配置了 `data-tauri-drag-region="false"`，且未提供原生拖拽事件驱动，导致用户无法拖动程序框；
3. **多选删除缺乏鼠标流接缝**：
   - 条目复选框仅在 `selectedIds.length > 0` 时渲染，常态下完全隐藏，鼠标无法主动点选进入多选，且浮动工具栏缺少显式的批量删除按钮；
4. **版本更新缺少主界面触达**：
   - 仅支持用户主动进入设置弹窗手动点击更新，启动无静默探测，主界面无法感知可用新版本。

## 方案选型与决策 (Decision)

经架构推演（`/grill-with-docs`），我们决定实施如下人机工效与交互升级：

### 1. 搜索框文案精简与头部自适应布局 (Compact Searchbar)
- 将冗长文案精炼为：`搜索历史 (按 / 聚焦，1~9 直贴)...` 与 `搜索常用短语 (/ 聚焦)...`；
- 优化第一行右侧控制组外边距与弹性伸缩，确保在所有屏幕缩放比例下占位文本完整且留白舒适。

### 2. 双区域原生窗口拖拽 (Window Dragging)
- 通过 Tauri 原生 `getCurrentWebviewWindow().startDragging()` 事件驱动，支持：
  - **顶部标题栏空白区域**：按住 Header 非输入框与非按钮的空白处即可自由拖拽；
  - **底部状态栏空白区域**：按住 footer 非交互按钮的空白处亦可平滑拖动；
- 手感媲美原生桌面应用，零视觉把手噪点。

### 3. 多选全链路激活与批量删除 (Batch Deletion)
- **悬浮露出复选框**：鼠标悬浮（hover）条目时，左侧按键槽位平滑显现复选框 `☐`，点击即可一键勾选进入多选态；
- **桌面级标准修饰点选**：支持 `Ctrl + 鼠标左键` 点选/反选与 `Shift + 鼠标左键` 连续多选；
- **多选工具栏显式「批量删除」**：在底部浮动栏显式呈现红色「🗑️ 批量删除 (X项)」按钮，并与 `Delete` 键秒删完美闭环。

### 4. 启动静默探测与非侵入式更新信标 (Update Beacon)
- **启动延迟静默探测**：应用启动 3 秒后后台静默发起 GitHub Releases 探测（静默容错）；
- **主界面多维更新信标**：
  - 右上角设置齿轮按钮上渲染发光微红点；
  - 第二行右侧与底部状态栏浮现可点击的醒目更新指示胶囊：`🚀 发现新版本 vX.X.X`；
  - 点击直达富文本更新日志卡片并支持一键覆盖升级。

## 架构影响 (Consequences)

- **正面收益**：
  - 搜索栏文字完整舒展，排版专业干练；
  - 窗口随心拖放，摆脱位置束缚；
  - 鼠标与键盘多选删除体验一致且操作直观；
  - 新版本感知度大幅提升，且绝不强弹窗打断日常工作流。
- **负面成本与注意事项**：
  - 拖拽事件触发需严格排除按钮与输入框，防止误触拖动。
