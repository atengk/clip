# 数据存储透明化、GitHub 在线更新检查与原生文件对话框灾备架构决策

## 背景与问题 (Context)

在日常使用 Clip 过程中，用户暴露出以下三大运维与体验痛点：
1. **数据存储黑盒化**：数据库（`clip.db`）与图片缓存（`blobs/`）默认存放在系统底层应用数据目录（`%APPDATA%\com.clip.app`），但界面中未展示该路径，用户无法获知占用大小，也无法一键打开目录排查；
2. **缺少版本感知与在线检查更新**：应用完全没有版本比对与检查更新入口，官方发布重要功能与修复后，用户处于完全的信息盲区；
3. **灾备归档（.clipbak）体验反人类**：备份导出与恢复要求用户手动键盘输入绝对文件路径，极易拼写错误或引发权限异常。

## 方案选型与决策 (Decision)

我们决定在现有单一 660×520 浅色流线型主面板架构下，全面重构这三大模块并实施以下架构决策：

1. **存储路径透明化与一键目录唤醒 (Data Directory Transparency)**：
   - 保持系统 `%APPDATA%\com.clip.app` 作为最安全规范的默认存储根目录，避免跨盘迁移带来的文件占用锁与权限风险；
   - 新增 `get_storage_info` 命令，实时采集数据库体积、图片缓存体积、条目总数与短语总数；
   - 新增 `open_storage_dir` 命令，支持一键在 Windows 文件资源管理器（Explorer）中唤起定位，同时支持单击复制完整存储路径。
2. **轻量在线更新检查与变更日志弹窗 (Update Checker)**：
   - 直连 GitHub Releases 开放 REST API（`https://api.github.com/repos/atengk/clip/releases/latest`），免鉴权且零第三方私有服务器运维负担；
   - 采用标准语义化版本比对（SemVer Compare）判定新版；
   - 发现新版时弹出专属弹窗，呈现版本号、发布日期与 Markdown 变更日志，并通过 `@tauri-apps/plugin-opener` 支持一键前往 GitHub Release 页面下载。
3. **原生系统文件选择对话框灾备重构 (Native File Dialogs)**：
   - 彻底淘汰手打文件路径文本框；
   - 导出备份时调用原生 SaveFileDialog，自动填充当前日期推荐名称（如 `Clip-Backup-YYYYMMDD.clipbak`）；
   - 导入恢复时调用原生 OpenFileDialog，严格限制 `.clipbak` 文件过滤，并附带二次合并安全确认。

## 架构影响 (Consequences)

- **优势**：
  - 数据存储完全透明可控，用户清晰感知磁盘使用情况并可一键定位物理目录；
  - 零运维成本实现版本快速迭代闭环，用户第一时间获知新版本特性；
  - 彻底终结手打路径的脆弱交互，灾备导入导出体验达到现代桌面软件黄金标准；
  - 核心逻辑保持毫秒级确定性测试，单测与 E2E 回归套件保持 100% 通过。
- **权衡**：当前在线更新未采用静默后台全自动替换二进制补丁机制，而是采用轻量透明的 Release 直达下载，规避了签名私钥托管与系统提权安装的复杂安全风险。
