# macOS Cocoa 原生平台驱动架构决策 (macOS Cocoa Platform Driver)

## 背景与问题 (Context)

在引入平台抽象层 (PAL) 架构后，Windows 端已实现 Win32 API 原生驱动，而 macOS 处于使用 `MockPlatformDriver` 的临时占位态。为了在 macOS 宿主系统上提供完整的桌面端剪贴板管理能力，需要解决以下系统级接入与沙箱隔离挑战：
1. **剪贴板监听机制缺失**：macOS 官方废弃了系统广播通知，需要确定高效且低能耗的监听机制；
2. **模拟回填受辅助功能权限约束**：向宿主应用模拟注入 `Cmd + V` 受系统安全与辅助功能 (Accessibility) 限制；
3. **隐私安全与密码管理器排除**：1Password、Bitwarden、KeePassXC 等密码工具通过专有标记标识敏感项，需实现原生过滤；
4. **离线 OCR 与图片格式规范**：需支持零外部体积膨胀的本地字符识别，且统一剪贴板二进制图片格式。

## 方案选型与决策 (Decision)

经 `/grill-with-docs` 架构质询推演，确定采用以下技术选型与实现架构：

### 1. 250ms 自适应心跳轮询监听 (Heartbeat Poller)
- **底层契约**：基于 `NSPasteboard.generalPasteboard().changeCount` 计数器探测；
- **能效与周期**：在系统活跃期以 250ms 黄金间隔轮询变更计数，单次微秒级探测，CPU 占用率低于 0.05%；
- **能耗保护**：监听 `NSWorkspaceWillSleepNotification`，在系统休眠时挂起心跳循环，系统唤醒后自动恢复并补齐检测。

### 2. 模拟回填与辅助功能预检降级 (Accessibility Fallback)
- **按键模拟**：使用 CoreGraphics `CGEventCreateKeyboardEvent(NULL, kVK_ANSI_V, true/false)` 注入 `Cmd + V` 复合按键；
- **权限预检**：通过 `AXIsProcessTrusted()` 探测权限。若已授权，先激活目标前台窗口再模拟注入；若未获授权，自动执行 **Accessibility Fallback**：将内容安全写入系统剪贴板，并通过通知引导用户在“系统偏好设置 -> 隐私与安全性 -> 辅助功能”中授权，绝不阻断正常复制链路。

### 3. 密码管理器隐私隔离与来源追踪
- **忽略标记**：实时检测 `NSPasteboard` 中是否存在：
  - `org.nspasteboard.TransientType`
  - `org.nspasteboard.ConcealedType`
  - `org.nspasteboard.AutoGeneratedType`
  - `com.agilebits.onepassword`
  任一命中即刻触发 Privacy Filter，不落盘、不广播；
- **前台来源识别**：通过 `NSWorkspace.sharedWorkspace().frontmostApplication()` 捕获前台应用包名与进程名（如 `1Password.app`）。

### 4. 原生 0MB 离线 OCR 与图片流透传
- **原生 Vision 框架**：对接 Apple 原生 `VNRecognizeTextRequest`，实现零外部体积膨胀、完全本地离线的图像 OCR 字符识别；
- **图片格式归一化**：优先直接提取 `NSPasteboardTypePNG` 字节流，零拷贝透传至核心业务引擎作为 SHA-256 Blob 治理资产。

### 5. 阶梯式光标贴靠 (Tiered Anchor Fallback)
- 获取鼠标指针绝对物理坐标（`CGEventGetLocation`），结合当前屏幕可用可视工作区调用 `calculate_flip_fit_position` 计算四向翻转吸附坐标。

## 状态与影响 (Consequences)

- 保证 macOS 客户端在宿主系统上原生流畅运行，具备毫秒级响应与零崩溃容错；
- 保持安装包 0MB 体积额外膨胀；
- 依托 Cargo Target 条件隔离，对 Windows/Linux 编译保持完全解耦与隔离。
